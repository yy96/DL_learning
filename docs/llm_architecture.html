LLM Architecture Map

A visual taxonomy of model backbones: encoder-only, decoder-only, encoder–decoder, dense Transformers, MoE, state-space models, recurrent models, and hybrids.

Read = encoder Write = decoder Route = MoE Stream = RNN / SSM Mix = hybrid
Encoder-only

BERT-style: “understand text”

Input tokens ↓ [Bidirectional encoder blocks] ↓ Contextual representations ↓ Classifier / embedder / reranker

Best for: classification, embeddings, search, reranking, extraction.

Think: a reader that sees the whole sentence at once.

Examples: BERT, RoBERTa, DeBERTa-like models.

Decoder-only

GPT-style: “predict next token”

Prompt tokens ↓ [Causal decoder blocks] ↓ Next-token probabilities ↓ Generated continuation

Best for: chat, completion, code, reasoning, creative generation.

Think: a writer that can only look left.

Examples: GPT-style, Llama-style, Mistral-style, Qwen-style models.

Encoder–decoder

T5-style: “read then write”

Input text → [Encoder] → memory ↓ Output prefix → [Decoder + cross-attn] ↓ Output text

Best for: translation, summarization, text-to-text transformation.

Think: read the source, then generate the answer.

Examples: original Transformer, T5, BART, FLAN-T5.

Dense Transformer

All parameters participate

Token ↓ Attention ↓ MLP ↓ Attention ↓ MLP ↓ Output

Best for: simplicity, predictable serving, smaller-to-mid models.

Think: every token uses the same full stack.

Tradeoff: easy to understand, but compute grows with model size.

Mixture-of-Experts

Many experts, few active

Token ↓ Router ↓ Expert 2 + Expert 9 ↓ Combine ↓ Next layer

Best for: scaling capacity without activating all parameters per token.

Think: a switchboard sends each token to specialists.

Examples: Switch Transformer, GShard, Mixtral-style, DeepSeek-style MoE.

State-space / SSM

Mamba-style: sequence state

token_t + state_t ↓ selective state update ↓ state_{t+1} + output_t

Best for: efficient long-sequence modeling research.

Think: a learned dynamical system flowing through tokens.

Examples: Mamba and Mamba-like models.

Recurrent

RWKV-style: RNN meets Transformer

token_1 → state_1 token_2 → state_2 token_3 → state_3 ... output_t from state_t

Best for: streaming and efficient inference experiments.

Think: Transformer-like training, RNN-like generation.

Examples: RWKV-family models.

Hybrid

Attention + SSM/RNN/MoE

Layer 1: full attention Layer 2: sliding attention Layer 3: SSM Layer 4: MoE MLP Layer 5: attention ...

Best for: balancing quality, context length, throughput, and memory.

Think: keep attention where it helps; replace it where it is expensive.

Examples: modern experimental long-context and efficient LLMs.

System architecture

RAG / tools / agents

User query ↓ Retriever / tools / memory ↓ LLM ↓ Answer / action

Best for: grounding, external knowledge, search, tool use, workflow automation.

Important: this often wraps the model; it is not always a new neural backbone.

Examples: RAG assistants, tool-using agents, coding agents.

Quick glossary

Encoder

A stack that reads an input sequence and builds contextual token representations. Usually bidirectional.

Decoder

A stack that generates output tokens. In GPT-style models, it is causal: it cannot attend to future tokens.

Cross-attention

Attention where the decoder queries the encoder output. Common in encoder–decoder models.

Dense model

A model where every token activates the same full set of layers and parameters.

Mixture-of-Experts

A sparse architecture where a router sends each token to one or more expert sub-networks.

State-space model

A sequence model that updates a hidden state through time, often with better scaling behavior for long sequences.

Hybrid model

A model that combines architectural families, such as attention layers plus state-space layers or MoE MLPs.
